# 24-hour team plan

Designed for the required 4–5 person team.

## Roles

### Person A — backend/integrations

- Google Docs adapter
- GitHub adapter
- persistence and API

### Person B — Mistral/evaluation

- structured schemas
- prompts
- Mistral gateway
- evaluation cases

### Person C — frontend/design

- setup screen
- inbox
- review surface
- patch diff

### Person D — product/demo

- user interviews
- demo fixtures
- pitch and Devpost
- testing PM language

### Optional Person E — workflow/reliability

- audio transcription
- approval/write path
- deployment
- integration testing

## Timeline

### Hour 0–1

- confirm rubric with staff;
- assign roles;
- create clean repository;
- redeem credits;
- test Mistral key;
- create Google folder and public demo GitHub repo.

### Hour 1–4

- boot frontend/backend;
- implement local demo mode;
- finalize UX wireframe;
- create seeded docs, code, and transcript.

### Hour 4–8

- Google Docs read;
- GitHub PR read;
- evidence normalization;
- frontend displays sources.

### Hour 8–12

- Mistral extraction;
- relation classification;
- first correct alert;
- evidence validation tests.

### Hour 12–16

- review UI;
- role explanations;
- patch generation;
- approve/reject.

### Hour 16–19

- Google Docs write-back;
- Voxtral or email;
- integration tests.

### Hour 19–21

- user test;
- fix false positives;
- harden demo;
- freeze features.

### Hour 21–23

- pitch rehearsal;
- Devpost materials;
- backup recording;
- deployment.

### Hour 23–24

- final smoke test;
- submit early;
- no risky feature additions.

## Feature-freeze rule

Once the end-to-end demo works, no new source integration may be added unless it directly improves a rubric category and cannot destabilize the main path.
